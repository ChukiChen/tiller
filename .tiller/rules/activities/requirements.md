# 需求编写

规则标识：ACT-REQ。形成或修改需求时使用。小改动可直接写入任务记录；总体或模块需求才建立独立规格。

## 本次需求

- 说明面向谁、要解决什么、本次范围、预期结果和已有依据。区分事实、假设、候选方案与已确认决定。
- 验收条件使用稳定编号，例如 `AC-1`。每条条件应可观察、可验证，写清正常、异常和边界行为。
- 大功能先写入 `.tiller/plans/`，把目标拆成有依赖的任务条目；小改动不必规划。
- 需求确认后、实现前，把每条 `AC` 转为新增或修改的全局用例，先写清前置条件、步骤、输入、预期结果、类型、优先级和来源 `criteria`；再让测试名或紧邻注释引用 `CASE-NNN`。
- 任务记录的需求固定写目标、范围、编号验收条件；另写的规格只作引用，不替代本次可执行正文。
- 没有依据时说明缺口，不把代码现状反推为已确认要求，也不虚构用户确认。

## 确认

先把目标、范围、关键行为和验收条件写进任务记录，再展示正文并确认。确认人默认取 Git `user.name`，可用 `--by` 指定；原话可选，只作附注。需求变化后重新核对。

需求确认后再形成对应设计。报告型工作可以只交付分析或审查结论，不自动进入实现。
