# 代码质量

规则标识：QUALITY-CODE。编写、修改或评审代码与测试时使用。

- **命名**：名称清楚表达用途，并与邻近代码保持一致；避免无意义缩写和含义不明的短名。
- **结构**：保持小步可改，模块边界清晰；职责变化时移动边界，而不是在现有函数里继续堆分支。
- **扩展性**：只为已经出现的真实变化预留扩展点；不为假想场景增加抽象。
- **反过度设计**：不过早泛化，不预建多层包装，不引入未使用的依赖、配置或开关。
- **可读性**：复杂逻辑写清意图和数据流；公共 API 保持稳定，内部实现可随证据简化。
- **边界校验一次**：未知输入只在边界校验并转换为类型化值，向内传递已校验数据；内部不重复堆防御。
- **保持简单**：能放在一个函数里就不要拆；单次使用的 helper 先内联，出现第二个真实调用再提取。
- **假想风险**：不为假想的竞态或安全边角静默增加复杂度；先说明失败模式、发生概率和代价，再决定是否加固。
- **注释**：只写非显而易见的约束、原因和取舍；不复述代码，不记录流水账。

以上是阅读和评审约定，不单独作为硬性扫描规则；与安全要求冲突时，先说明威胁和代价。
