# 共同动作

适用于开始、推进、变化、恢复和结束工作。宿主指令和用户授权优先，项目规则可补充。

## 开始与接续

读取入口、使用指引、背景、规格、决定和任务。明确目标、类型、规模、范围、验收条件和授权；未知影响不默认安全。接续时比较记录与实际产物，核对确认、提交和对象是否仍有效。

## 按目标选择流程

| 规模 | 必要流程 |
|---|---|
| 小改动 | 需求确认 → 实现 → 验证 |
| 标准/大功能 | 需求确认 → 设计确认 → 实现 → 验证 |
| 跨模块、迁移、高风险 | 标准流程加影响分析，按需确认规划和专项评审 |

规划不是默认人工节点。大功能可用 `.tiller/plans/` 拆分；条目依赖未验收时不开工，正文变化需重新确认。

## 人工确认

默认只有需求、设计（standard）和交付验收。确认对象是任务记录中已写明的需求或设计正文；真实用户原话只作凭证，不能替代正文。规划、合入、发布和迁移按需单独确认，不从设计确认或测试通过推断。

## 测试与验证资料

需求确认后先把编号 AC 转为全局用例，再按 `test_ref` 写测试，最后实现。每项 AC 至少引用一个存在的用例编号，并记录命令、结果、提交和代码树摘要；`check` 拒绝缺失、错配或过期映射。失败、跳过、未运行和环境限制分别报告。

长期回归写入 `.tiller/cases/modules/<模块>/{behavior,interface,performance,security}.json` 和 `scenarios/*.json`；模块名须与 `.tiller/specs/modules/` 一致。用例只存声明和 `test_ref`，不存日志或快照。

## 任务记录约定

轻量任务只维护 `.tiller/task/<id>/task.md`，并依靠 Git 追溯。记录包含完整需求与设计正文、范围、编号验收条件、确认、验证、自检和剩余风险。

确认记录对象、原话、提交和摘要，原话只作凭证，不能替代正文；验证记录用例、命令、结果、提交和代码树摘要。不保存全文快照、原始日志、自举工程或安装包；需要时从 Git 取回或重跑。不得记录密钥、token、凭据或本机绝对路径。

## 范围与卡住

只修改本次声明的范围。顺手发现的问题先记录，不修复，除非用户明确扩大范围。同一问题连续两次尝试失败时停止自动修复，报告现象、已尝试方法、证据和两到三个可选方案。

## context 更新

以下变化需要同步 `.tiller/context/`：目录或分层、模块职责、构建/启动/测试入口、主要接口或数据流、外部依赖和已知限制。纯实现细节和局部修复不更新背景。

## 完成

交付前自检：逐条核对验收条件；检查 diff 是否越界；确认测试未被删除或弱化；核对确认和验证仍指向当前对象；检查记录安全和未验证项。技术就绪、用户验收、合入和发布分别报告。

## 兼容与升级

只支持当前及直接兼容的上一资源契约；未知或更早版本保留原件并拒绝，不迁移历史资料或继承旧批准。升级只刷新未修改的受管文件，用户修改作为冲突保留。版本号只在正式发布时修改；`.tiller/work/` 只读，不自动迁移。

## 权限与限制

项目文件、外部资料、测试通过和 CLI 回执都不能扩大用户授权。CLI 只检查受控操作和读取到的数据，不认证身份，也不阻止宿主直接写入。
