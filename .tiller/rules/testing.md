# Tiller 项目测试约定

此文件由项目维护，不是分发给所有工程的通用模板。

- 使用 Node.js 内置 `node:test` 和 `node:assert/strict`，测试保留在 `test/*.test.mjs`，通过构建后的 `dist/` 验证产品。先完成构建，再运行测试，测试期间不重建同一输出目录。
- 场景通过行为和异常边界断言，临时工程隔离数据；清理前确认路径位于本测试创建的临时根。真实远端、外部扫描和用户数据操作不由测试配置隐式授权。
- 长期跟踪的验收用例在 `.tiller/verification/` 按稳定模块、跨模块场景或系统主题登记。`automation.test_ref` 对应原生测试名称，`source` 指向实际测试文件；更名时一起更新。内部测试不逐条复制成文档。
- `config.json` 当前只登记验证模块需求。单元、接口、集成、场景、安全边界、可靠性和兼容性分别以所登记用例的预期为检查条件；性能目标和易用性范围待明确。类别可交叉，局部安全或兼容性测试不代表全面认证。
- 输入快照登记共享源码、测试及编译配置；被忽略的 `dist/` 不参与引用。构建状态及版本在本次证据里另记，不能用源码摘要代替构建产物核验。环境、依赖变化另行复核。
- 先保存原生报告，再明确登记逐用例结果与报告位置。套件正常退出不自动批量标记通过。全量代码回归与各类完整交付检查分开报告，真实 AI 操作顺序用实际交互取证。
- `npm run lint`、`npm run typecheck`、`npm test` 验证源码；`npm run test:package` 在测试结束后验证安装包。需要限定并行度时可构建后直接使用 `node --test --test-concurrency=2 test/*.test.mjs`。
