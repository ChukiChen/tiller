# Tiller 项目测试约定

此文件由项目维护，不是分发给所有工程的通用模板。

- 使用 Node.js 内置 `node:test` 和 `node:assert/strict`，测试保留在 `test/*.test.mjs`，通过构建后的 `dist/` 验证产品。先完成构建，再运行测试，测试期间不重建同一输出目录。
- 场景通过行为和异常边界断言，临时工程隔离数据；清理前确认路径位于本测试创建的临时根。真实远端、外部扫描和用户数据操作不由测试配置隐式授权。
- 验收条件使用 `AC-N` 编号，每项先映射 `.tiller/cases/` 全局用例，再由用例的具名 `test_ref` 映射实际测试；由 `verify` 记录命令、结果、提交和代码树摘要，由 `check` 核对覆盖与新鲜度。不另建证据包或逐条复制测试报告。
- 单元、接口、集成、场景、安全边界、可靠性和兼容性按实际影响选择；性能目标和易用性范围按任务补充。类别可交叉，局部安全或兼容性测试不代表全面认证。
- 原始输出只写 `.tiller/local/logs/`，默认不显示、不提交；不提交输入全文快照、生成工程或安装包。需要细节时从 Git 取回或重新运行命令；失败、跳过、未运行和环境限制分别报告，不能因套件正常退出而批量写成通过。
- `npm run build`、`npm run lint`、`npm run typecheck`、`npm test` 验证源码；`npm run test:package` 在测试结束后验证安装包。需要限定并行度时可构建后直接使用 `node --test --test-concurrency=2 test/*.test.mjs`。
