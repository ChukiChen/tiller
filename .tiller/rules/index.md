# tiller 规则索引

这些是随工程接入的通用规则。实际资源版本以 `.tiller/project.json` 中的 `resourceVersion` 为准；项目自定义规则和已有约定继续适用，CLI 更新不等于工程规则自动更新。

## 读取顺序

1. 每次开始或接续都读[共同动作](core.md)，新建、补充及接续工作前必读其中的[工作记录约定](core.md#工作记录约定)，并查找本目录实际存在的项目规则（如 `project.md`）及[工程索引](../index.md)登记的既有约定；不假定示例文件一定存在。
2. 按当前活动读取下表中的规则；切换活动、仓库或规则版本时补读。
3. 核对工作记录中的规则来源和实际内容。多个规则无法同时满足时说明冲突，依照宿主指令和明确授权解决，不能静默放宽完成条件。

共同动作定义人工确认的边界：需求确认后设计、设计确认后实现，交付验收、合入和发布分别确认。每次切换环节均核对具体内容与实际用户决定；读取专项指引或生成模板不表示节点已通过。阶段内符合授权的工作自主推进。涉及代码交付时必读[隔离开发约定](core.md#隔离开发与评审合入)，核对管理方式、活动位置和操作权限。

| 当前活动 | 执行指引 | 质量检查 |
|---|---|---|
| 接手已有项目或确定局部变更依据 | [已有项目接手](core.md#已有项目接手) | [验证依据](quality/verification.md) |
| 建立或调整项目专属开发约定 | [项目开发规范](core.md#项目开发规范) | [验证依据](quality/verification.md) |
| 形成总体、模块或变更需求 | [需求编写](activities/requirements.md) | [文档质量](quality/documents.md) |
| 形成总体、模块或变更设计 | [设计编写](activities/design.md) | [文档质量](quality/documents.md) |
| 安排功能分块、骨架及实施依赖 | [功能分块与实施安排](core.md#功能分块与实施安排) | [验证依据](quality/verification.md) |
| 修改代码、配置或测试 | [实现](activities/implementation.md) | [验证依据](quality/verification.md) |
| 验收、交付、发布或交接 | [交付](activities/delivery.md) | [验证依据](quality/verification.md) |

模板辅助组织内容，不替代规则或评审。已有文档能够承载必要信息时优先复用，不因格式不同要求重写。通用规则不指定业务技术栈、文档语言或项目发布政策；这些由实际项目约定及授权确定。
