# 工作推进设计

## 1. 任务模型

任务文件包含标题、一行 `tiller-task:v1` 元信息和可读区段。元信息保存 id、类型、规模、创建时间、Git 基线、范围、开工前摘要、可选规划归属、分支描述、标题摘要和结构化格式标记。需求、AC、设计、确认、验证、自检从 Markdown 区段读取；元信息与区段都受格式校验。

## 2. 状态与确认

`confirm` 计算对象摘要：

- requirements：类型、规模、范围、需求正文和 AC；
- design：需求摘要和设计正文；
- acceptance：需求、设计、AC 验证结果、提交和代码树。

正文变化导致对应摘要变化，`check` 将需求或设计确认独立标为失效。确认记录保存确认部分、确认人、时间、提交、摘要和可选原话；确认人优先用 `--by`，否则读取 Git `user.name`。验收前必须已通过技术自检。

新任务把结构化需求写在 `### 目标`、`### 范围`、`### 验收条件`，standard 设计写在 `### 方案`、`### 取舍`、`### 影响与风险`。旧任务没有格式标记时使用旧正文和顶层 AC；旧 quote 确认继续解析，写回时保留旧样式。

任务阶段在读取时按事实重新推导，优先级为最近关闭/放弃、有效需求确认、有效设计确认（standard）、当前验证、最后一次重开后的有效验收。回退时返回当前阶段与原因；`resume` 列表和 `plan status` 复用同一函数，避免多处状态漂移。

## 3. 验证

`verify` 只接受 AC、测试引用和 `--run "<命令>"`；记录的命令就是实际执行的命令，退出码决定 passed/failed，测试输出决定证据是否已核实。node:test TAP/spec 解析器由 `src/test-output.ts` 注册，按 `文件::测试名` 核实具名测试出现并通过；仅引用文件时要求测试存在且失败数为 0。无法解析或未命中的执行记录标记 `unverified`，由 `check` 阻断。历史记录没有核实字段时保持旧解析路径，不施加新证据检查。

外部报告使用 `--reported --command --result --reason`，理由必填并标记 `not-run`；`check`/`accept` 默认阻断，只有 `--allow-reported` 放行，`pr` 在验证结果中标明未执行及理由。bugfix 的 `--expect-fail` 在任务基线提交的临时 Git 工作树运行当前测试文件，要求具名测试失败并记录基线提交；`check` 还要求当前代码存在同一测试的已核实通过记录。工作树在成功或异常时都清理。

## 4. 检查

`check` 从任务记录和文件系统重建状态：

- 需求/设计确认是否仍绑定当前对象；
- 每条 AC 是否有最新通过、存在且未过期的测试；
- 执行记录是否已核实，外部报告是否有理由并经显式放行，bugfix 是否具备失败先行和当前通过；
- 用例是否存在并与测试引用一致，`criteria` 是否回指当前 AC 或在本任务修改；
- 用例库结构与模块/场景引用；
- Git 范围内的越界、未提交改动、删除/跳过/弱化测试；
- 记录中的密钥和本机路径。

结果分为阻塞项、提示、逐项覆盖和可写入 `task.md` 的自检清单。`accept` 复用同一检查，防止技术未就绪时写入验收。

## 5. 关闭与恢复

`close` 只接受当前阶段为已验收的任务；未验收任务必须显式 `--abandon`。关闭事件写入 `task.md` 的“关闭”区段，保存状态、原因和时间。`reopen` 追加恢复事件；验收、确认和验证仍按原摘要判断，阶段从最后一次恢复之后的事实重新计算。终态任务上的 `confirm`、`verify`、`accept` 直接阻塞。

## 6. 交付草稿

`commitTypeForTaskType` 将任务类型映射到限定提交类型；`taskCommits` 读取 `base..HEAD` 的非合并主题。`branchNameIssue` 校验 `类型/任务编号[-描述]` 及任务编号前缀；`currentBranch` 在 main/master、detached HEAD 或无 Git 时跳过。

`draftPullRequest` 复用 `inspectFlow` 的 AC 覆盖状态，从任务范围的模块路径、“涉及模块”声明和全局用例来源按声明顺序推导模块，标题取首个主模块，无模块时省略括号。标题摘要依次取 `pr --summary`、任务元数据 `summary`、任务基线后最早的规范 feat/fix 提交摘要和任务标题。提交读取保持正序，正文生成器只接受五个固定二级标题；关联任务输出纯文本路径，验证结果以每条 AC 的摘要行加普通嵌套记录呈现，不使用编号圆点。Markdown 在标题后单列建议分支，JSON 同时返回 `body`、`branch` 和提交列表。分支描述依次读取 `pr --slug`、任务元数据 `slug`、当前分支匹配描述，并统一规范化为小写字母、数字和连字符。该模块没有网络依赖，文案对 PR/MR 中性。

## 7. 范围与恢复

范围是工程相对路径集合；默认 `.`。排除任务自己的记录、`.tiller/local/`、`.git/` 和依赖目录。无 Git 时跳过依赖提交差分的检查，但保留文件级代码树摘要。写入使用统一事务，失败可用 `recover`。
