# 关键节点人工确认

日期：2026-10-15

状态：用户审阅设计及约束边界后要求继续，已按[开发计划](plan.md)准备 0.2.0 实现并通过本次检查；交付尚待用户验收。

## 问题与依据

外部学生服务试用中，AI 将“Java 接口、增删改查、内存实现”的方向确认扩展为行为与设计确认，先后顺序被合并成文档与代码一次写入。现有规则中的自主推进和简化条款未明确限制这种解释。

用户明确要求流程中的关键节点经人工确认后才能继续，并要求修改。先形成并展示需求变更稿及下一步；随后用户回复“继续”，按这一上下文接受本次需求变更作为设计依据并继续设计，不解释为对尚未展示设计的确认或实现授权。

## 需求变更

- [总体需求 R3](../../specs/requirements.md#r3-控制执行范围)：说明关键人工确认与阶段内自主推进的边界，补充整体验收方向。
- [工作推进 FLOW-15](../../specs/modules/workflow/requirements.md#flow-15-在关键节点取得人工确认)：提出需求确认、设计确认、交付验收、发布确认四类节点，定义具体内容、用户决定、复用、变化、例外及越过节点后的处理；同步现有流程、接续和完成条件，增加 AC-25 至 AC-32。
- [开发规范需求](../../specs/modules/standards/requirements.md)：要求规则落实这些边界，区分一般授权与具体确认，增加 AC-17 至 AC-20。

需求阶段只描述行为与结果；确认记录格式、命令、状态与约束机制随后在设计阶段细化。

## 本次设计采用的需求范围

1. 默认节点及顺序：需求确认后设计，设计确认后实现；交付验收与发布确认分开。
2. 确认必须对应实际用户决定及具体内容；通用推进指令、文件状态和自动检查不能替代确认。
3. 实质变更重新确认受影响范围，有效的已有确认可复用；节点简化或决定委托须有明确范围的用户授权。
4. 待确认状态在接续时保留；已有代码不能反推曾经确认，不补造历史。

## 已采用的设计与实现边界

- [总体设计](../../specs/design.md)：关键确认作为前置依赖，保持总体概览。
- [工作推进设计第 4 节](../../specs/modules/workflow/design.md#4-推进机制与状态判断)：四类节点、内容快照、来源核对、状态派生、变化及接续。建议按需新增独立的确认记录，保留历史，不把状态布尔值当作授权。
- [工作推进设计第 9 节](../../specs/modules/workflow/design.md#9-cli-能力与验证安排)：提出请求确认、记录决定、检查节点三个接口；纯 CLI 的结构检查不代替用户来源核验，旧版完成记录不当作人工验收。
- [开发规范设计](../../specs/modules/standards/design.md#41-规则资源的具体修订)：明确入口、共同规则、专项规则与模板的修改位置；简化文档不简化确认条件。
- [初始化设计第 8.5 节](../../specs/modules/initialization/design.md#85-人工确认规则的接入与已有工程更新)：新工程接入、已有工程预览后更新、用户修改保护及历史兼容。

上述设计已作为本次实现依据。关键限制是：共享本地文件可以记录真实决定，但不能防止同权限执行者伪造；当前对话可核对实际用户输入，跨工具无法核对来源时需重新取得确认。自动放行需要独立来源核验能力，阻断宿主直接写代码则另需宿主操作拦截，不能由一个新 CLI 命令替代。

正常人工协作不依赖尚未实现的身份适配：执行者核对真实用户输入后，可以保存标明 `reported-review` 的确认和完成记录，明确未由程序独立认证；只有来源引用而没有实际复核不能通过。`verified-source` 专用于独立适配核验成功，不能由执行者自行选择。两种依据均不扩展原批准范围。

## 验证与现状

需求阶段进行了文档检查：六个修改文件的相对文件链接、需求编号唯一性、验收需求引用及行尾空白检查通过。工作推进包含 15 条需求、32 个验收场景，开发规范包含 10 条需求、20 个验收场景；当时仅核对文档，未据此宣称机制已实现。

设计阶段已核对六个变更文件的链接、锚点与行尾空白，工作推进 32 项、开发规范 20 项、初始化 18 项验收均有设计对应。独立审查发现正常用户验收后的保存路径不能依赖未来身份适配，已补充执行者复核与程序认证的区别及正常完成验证场景，修订复核通过。

实现阶段已更新根入口、分发规则和模板，并实现确认请求、决定记录、节点检查、设计前置条件、验收完成条件及显式升级。tiller 自身和外部 Java 工程已从 0.1.0 更新到 0.2.0，外部工程业务代码、测试及历史记录保持原状。具体接口和能力边界见[实现记录](implementation.md)。

最终 lint、类型检查、构建及 63 项自动测试通过，隔离安装的 9 项检查通过。独立临时 Java 工程的两次实际 AI 行为验证均停在需求待确认，第二次接续未把一般继续指令视为批准；换行兼容修复后工程状态复验通过。检查过程、升级比对及未验证范围见[验证记录](verification.md)，不以这些样例宣称能强制拦截所有宿主写入。

工作目录新增 `YYYYMMDD-主题` 命名建议，日期取创建日且接续稳定；CLI 支持显式日期标识并兼容旧标识，不自动补日期或改名历史工作。
