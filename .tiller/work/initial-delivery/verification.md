## 审查与修复

独立审查发现并修复：Windows 大小写路径绕过独立证据与本机目录边界、无效 Git 标识被误认成仓库、本机忽略文件反向包含恢复原件、被 Git 忽略的评审依据可被用作共享证据。修复均加入回归测试，增量审查确认原问题已关闭。

真实起草首次发现索引全文摘要会阻断 AI 正常维护资料链接。现仅保护固定导航区段，链接维护保留；新增回归覆盖创建工作、更新链接、重复初始化与成功接续。修复后从新的安装包和独立工程重新进行宿主验证，没有把失败的初次尝试当作通过。

## 宿主文档工作验证

独立验证工程使用虚构的个人本地书签需求，位于外部临时 Git 仓库。已有本地背景明确添加、检索、删除能力及三个待定问题；先由安装后的 CLI 创建草稿，再运行实际 AI 起草和新会话接续。完整过程及结果见[宿主验证记录](verification.md#宿主接续验证)。

宿主命令执行入口出现启动失败，AI 改用可用的文件读写能力。CLI 命令由本次交付的执行环境另行验证；没有将文件读写冒充宿主内成功执行 CLI。文件接入与该次实际行为分别记载，`status` 保持 `hostVerification: not-verified`，不会把一次人工验证推广为所有工程的宿主保证。

## 保留边界

- 文档结构检查不判断需求语义或用户是否批准；评审须核对实际内容。
- 锁协调本 CLI 的写入，无法保证排除所有外部进程在检查和替换之间的瞬时竞争。
- 本机事务记录支持文件操作恢复，不替代版本管理或跨机器恢复；非 Git 工程不宣称已纳入版本控制。
- 受管规则修改会保留并阻止继续写入，当前尚无协调或迁移命令；索引资料链接与项目自定义规则可独立维护。
- 历史迁移、远程获取、模式切换、完整任务调度、全部平台矩阵和完整生命周期自举尚未完成，不在本次已确认交付范围内。

## 准备与执行

使用 `npm run test:package` 生成并隔离安装的 0.1.0 包，在外部临时 Git 工程中创建 `product-outline` 文档工作。该工程与 tiller 源码分开，路径含中文和空格。背景是一项虚构的个人本地书签需求：添加、关键词检索、删除，无账户或云同步；重复链接合并、导入导出、数据恢复保持未决。

两次调用均使用 Codex CLI 0.162.1 的 `exec --ephemeral --sandbox workspace-write --json -C <工程>`。第二次新建上下文，没有使用宿主 resume 或传入第一次聊天历史，仅通过工程文件接续。

第一次输入：

> 为这个项目起草总体需求，先明确尚缺信息，不开始编码；本轮只完成目标与范围，保存进展和下一步后停止。

第二次输入：

> 继续 product-outline 的总体需求文档工作，保留尚未决定的问题，完成可供讨论的需求草稿并留下实际检查依据；不开始设计或编码。

## 限制与历史问题

首次试验发现整份索引校验会阻断正常维护；修复并补回归后，重新打包、建立独立工程，再执行上述两次调用。旧失败未作为通过依据。

宿主的命令执行入口启动失败，两次均改用可用文件操作完成读取、写作和检查。因此实际验证了规则读取及文件接续，没有证明该宿主配置内 CLI 调用可用。CLI 初始化、接续、检查及完成由外层环境另行实际执行。

语义复核发现并修正正文与过程记录混杂，说明可读规则需要实际审阅配合；CLI 的结构通过不保证内容组织正确。这里使用有意保存进度的停止点验证新上下文恢复，异常文件事务中断另由自动测试覆盖。

原始调用日志和外部测试工程仅保留于本机临时目录；可共享的结果摘要、各阶段内容摘要及最终状态见宿主验证快照（原过程文件已清理），不依赖临时日志作为唯一完成依据。
