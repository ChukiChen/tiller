# 首个可用交付验证

日期：2026-10-14。对象：tiller 0.1.0 的当前工程接入、已有本地多仓库管理、规则与索引、文档工作及接续；不是完整产品需求的全部验收。

## 环境与范围

实际环境为 Windows，Node.js v22.23.2、npm 10.9.8、Git 2.55.0.windows.4。宿主验证使用 Codex CLI 0.162.1 的两次独立非交互调用，不复用对话历史。macOS、Linux 及其他宿主尚未实测。

收尾核对：27 份当前工程文档中的 136 处本地引用均存在，29 个源码、配置和资源摘要与测试时一致。历史归档保持原貌，不将其过时引用作为当前入口。自身资料索引补入验证链接后，`status` 仍就绪，重复 `init` 返回 `changed: false`；Git 差异空白检查通过。

## 审查与修复

独立审查发现并修复：Windows 大小写路径绕过独立证据与本机目录边界、无效 Git 标识被误认成仓库、本机忽略文件反向包含恢复原件、被 Git 忽略的评审依据可被用作共享证据。修复均加入回归测试，增量审查确认原问题已关闭。

真实起草首次发现索引全文摘要会阻断 AI 正常维护资料链接。现仅保护固定导航区段，链接维护保留；新增回归覆盖创建工作、更新链接、重复初始化与成功接续。修复后从新的安装包和独立工程重新进行宿主验证，没有把失败的初次尝试当作通过。

## 宿主文档工作验证

独立验证工程使用虚构的个人本地书签需求，位于外部临时 Git 仓库。已有本地背景明确添加、检索、删除能力及三个待定问题；先由安装后的 CLI 创建草稿，再运行实际 AI 起草和新会话接续。完整过程及结果见[宿主验证记录](host-verification.md)。

宿主命令执行入口出现启动失败，AI 改用可用的文件读写能力。CLI 命令由本次交付的执行环境另行验证；没有将文件读写冒充宿主内成功执行 CLI。文件接入与该次实际行为分别记载，`status` 保持 `hostVerification: not-verified`，不会把一次人工验证推广为所有工程的宿主保证。

## 保留边界

- 文档结构检查不判断需求语义或用户是否批准；评审须核对实际内容。
- 锁协调本 CLI 的写入，无法保证排除所有外部进程在检查和替换之间的瞬时竞争。
- 本机事务记录支持文件操作恢复，不替代版本管理或跨机器恢复；非 Git 工程不宣称已纳入版本控制。
- 受管规则修改会保留并阻止继续写入，当前尚无协调或迁移命令；索引资料链接与项目自定义规则可独立维护。
- 历史迁移、远程获取、模式切换、完整任务调度、全部平台矩阵和完整生命周期自举尚未完成，不在本次已确认交付范围内。
