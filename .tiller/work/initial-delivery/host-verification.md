# 文档工作与新会话接续验证

日期：2026-10-14。结果：完成一次真实文档起草、保存停止点、独立会话接续、复核及 CLI 交付记录。此次验证证明已观察到的行为，不证明所有宿主或所有任务都会遵循规则。

## 准备与执行

使用 `npm run test:package` 生成并隔离安装的 0.1.0 包，在外部临时 Git 工程中创建 `product-outline` 文档工作。该工程与 tiller 源码分开，路径含中文和空格。背景是一项虚构的个人本地书签需求：添加、关键词检索、删除，无账户或云同步；重复链接合并、导入导出、数据恢复保持未决。

两次调用均使用 Codex CLI 0.162.1 的 `exec --ephemeral --sandbox workspace-write --json -C <工程>`。第二次新建上下文，没有使用宿主 resume 或传入第一次聊天历史，仅通过工程文件接续。

第一次输入：

> 为这个项目起草总体需求，先明确尚缺信息，不开始编码；本轮只完成目标与范围，保存进展和下一步后停止。

第二次输入：

> 继续 product-outline 的总体需求文档工作，保留尚未决定的问题，完成可供讨论的需求草稿并留下实际检查依据；不开始设计或编码。

## 观察到的结果

| 环节 | 实际证据与判断 |
|---|---|
| 入口与规则 | 两次执行记录均显示读取工程入口、规则索引、共同动作、需求编写和文档质量规则，再读取实际背景、草稿与工作记录 |
| 初次起草 | 在已有草稿中填写目标和范围，保留三个未决问题；更新工作进展、下一步及索引，按要求停止，没有编写产品代码 |
| 停止点 | 首次结束后，CLI `status` 就绪，`work resume product-outline` 能读取原草稿和停止点；机器状态仍为 `draft` |
| 新上下文恢复 | 第二次从保存文件恢复相同产品、范围与未决问题，沿用唯一需求正文，补充使用场景、核心需求及验收方向，保存检查记录 |
| 内容复核 | 原问题未被擅自确认；发现总体需求混入本次文档交付安排、阶段变化和下一步，由主执行方移出需求正文，过程记录仍保留在 `work.md` |
| 修订后检查 | 对实际修订内容复核，27 处已有本地引用可达，另有指向本次复核文件的引用；需求、场景及验收对应，原证据明确标为历史 |
| 交付记录 | 外层环境执行安装包中的 `work check` 通过，随后 `work complete --evidence .tiller/work/product-outline/review.md` 成功；再次 `resume` 返回 `complete`、`ready: true` |

最终文档仍为未确认讨论稿。文档编写交付、用户确认和产品实现分别记录；此次没有设计、编码、Git 提交或发布。

## 限制与历史问题

首次试验发现整份索引校验会阻断正常维护；修复并补回归后，重新打包、建立独立工程，再执行上述两次调用。旧失败未作为通过依据。

宿主的命令执行入口启动失败，两次均改用可用文件操作完成读取、写作和检查。因此实际验证了规则读取及文件接续，没有证明该宿主配置内 CLI 调用可用。CLI 初始化、接续、检查及完成由外层环境另行实际执行。

语义复核发现并修正正文与过程记录混杂，说明可读规则需要实际审阅配合；CLI 的结构通过不保证内容组织正确。这里使用有意保存进度的停止点验证新上下文恢复，异常文件事务中断另由自动测试覆盖。

原始调用日志和外部测试工程仅保留于本机临时目录；可共享的结果摘要、各阶段内容摘要及最终状态见[宿主验证快照](host-verification-snapshot.json)，不依赖临时日志作为唯一完成依据。
