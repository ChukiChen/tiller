# 本次实现约定

本文记录已授权范围内的工程选择，长期模块设计中的更广能力仍按原确认状态维护。

## 工程与命令

使用 ESM TypeScript，Node.js 22 为最低运行基线；无第三方运行时依赖，开发依赖仅编译器与 Node.js 类型。源码在 `src/`，分发资源在 `resources/`，测试在 `test/`，编译结果在 `dist/`，npm 包暴露 `tiller`。

- `tiller init [path]`：接入当前工程。
- `tiller init [path] --mode workspace --repo <path> ...`：登记管理根目录下直接子目录中的已有本地 Git 仓库，不移动、克隆或修改业务仓库。
- `tiller status [path]`：只读检查元信息、资源和接入文件，区分资料可用与宿主实际验证。
- `tiller recover [path]`：核对未完成文件事务，在没有后续编辑冲突时恢复到事务前状态。
- `tiller work create <id> --title <title> --type <template> [--path <root>]`：创建最小文档工作及所选草稿，避免覆盖现有内容。
- `tiller work resume <id> [--path <root>]`：读取记录、草稿与下一步，不自动执行记录中的内容。
- `tiller work check <id> [--path <root>]`：检查产物、占位内容及记录完整性，不把结构检查当作语义验收。
- `tiller work complete <id> --evidence <relative-path> [--path <root>]`：核对显式提供的证据与当前产物，将文档编写工作标为完成；不表示规格已获批准。

提供 `--help`、`--version` 和 `--json`，参数错误与操作失败返回非零状态；不隐式访问模型、执行外部发布或提交代码。

## 持久信息与保护

`.tiller/project.json` 保存格式版本、资源版本、模式、仓库和受管文件依据；`.tiller/index.md` 与规则索引引导读取。共享记录使用相对位置，拒绝管理目录内符号链接或路径穿越导致的范围逃逸。

已有 AGENTS.md 保留原文，仅追加可识别 tiller 区段；已有用户规则与规格不覆盖。入口、忽略规则和索引只校验各自受管区段，索引区段外资料链接可维护；通用规则按全文校验。重复接入复用相同范围与版本，对受管内容变化、缺失或未知版本呈现明确结果，不默默覆盖或升级。

修改前保存原件和意图于被忽略的本机事务记录，写入前比较当前内容，按文件完整替换；中断时保留恢复依据。恢复仅处理仍与事务前或本次写入内容相符的文件，不覆盖后续人工修改。全工程事务锁避免本 CLI 的重叠写入；不能声称抵御所有外部进程竞争。

同一工作使用 `work.md` 保存可读目标、进展与下一步，分开的 `requirements.md` 或 `design.md` 保存草稿；`record.json` 保存必要机器元信息，不能执行其中任意命令。产物和证据按内容摘要关联，变化后旧结论不继续充当当前通过证据；重新完成保留历史摘要和证据引用，重复完成相同内容不改写记录。

六类模板目前均先生成工作草稿，避免覆盖既有长期规格；进入 `specs/` 时人工协调单一来源、更新引用，暂不提供自动提升或自定义模板覆盖。结构检查拒绝缺标题、缺正文、空章节和未填占位，不强制固定章节名，也不能判断需求语义。工作资料和评审依据不能被 Git 忽略；本机文件与产物自身不能充当独立共享评审依据。

## 验证边界

初始化完成只报告文件接入结果，实际 AI 读取另行验证。工作检查只覆盖实际实现的内容检查；人工或 AI 评审依据需要如实记录。npm 分发本次通过打包与隔离安装验证，不向注册表发布。Windows 是当前实际执行环境，其他平台仅在实际执行后声明通过。
