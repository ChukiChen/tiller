# 首个可用交付开发计划

## 顺序与职责

1. 记录已确认范围和实现约定，更新当前项目阶段。
2. 建立 TypeScript 编译、npm 命令入口及基于 Node.js 内置测试能力的验证配置。
3. 实现安全文件处理、两种初始化、版本检查、已有入口与忽略规则协调、事务记录及恢复。
4. 编写通用执行规则、质量指引与必要文档模板，避免携带 tiller 自身的专属约定。
5. 实现文档工作创建、只读接续、检查与明确完成操作，保留真实记录和证据。
6. 验证正常和异常场景，检查 npm 包的实际安装执行，进行独立审查并修复问题。
7. 用隔离测试工程验证文档起草与新上下文接续，记录真实能力、限制及剩余工作。

初始化核心、通用资源和集成测试可以独立并行，CLI 与工作操作由主负责人集成。每一项修改保留已有内容，不回退其他人的改动。

## 完成依据

- 编译及严格类型检查通过，相关自动测试通过。
- 两种初始化均可用；重复执行、用户改动、未知格式、路径越界和未完成操作都有明确行为。
- npm 打包包含编译入口及资源，可从打包结果安装并在中文及空格路径运行。
- 真实文档工作可产生草稿、保存未决问题、在新上下文中接续；文档完成不等于产品实现或内容获批。
- 平台验证与宿主接入验证只报告实际执行范围。未执行系统不宣称通过。

## 执行结果

七项工作已完成，实际证据见[验证记录](verification.md)和[宿主接续记录](verification.md#宿主接续验证)。初始化核心、资源与测试先并行实施，再集成审查；独立审查问题及真实起草发现的索引冲突均修复并复验。共 37 项测试通过，打包与隔离安装通过，tiller 自身完成工具化接入。

文档接续包含两次独立上下文及后续内容复核；宿主内命令入口不可用，采用文件操作，CLI 在外层环境实际执行。平台仅实测 Windows，其他环境与完整产品能力不作为本次完成结论。
