# 独立管理仓库布局需求

## 目标与范围

独立管理工程将业务仓库集中放在 repositories/ 下，与 .tiller/ 分开；管理资料和各业务仓库保持独立 Git 历史。单仓库内部集成方式不变。

## 行为及验收

- 仓库标识 service-a 与相对存放路径 repositories/service-a 分开记录；工作、确认及交付引用稳定标识。
- 初始化、状态检查、资料引用、隔离开发和恢复使用登记路径，不能把标识直接拼为目录。
- 管理仓库忽略 repositories/，业务仓库仍可独立提交；worktree 内业务目录仍按 repositories/<标识> 组织。
- 保留旧直接子目录布局的可读及显式升级能力，不自动移动已接入工程或改变历史仓库标识。
- 拒绝越界、非法映射、重复标识、符号链接及 Git 身份冲突；不覆盖已有目录。
- 本地新多仓库测试工程按新布局移动，保留三个仓库的提交和远端；仍留给用户从初始化开始测试。

## 依据与待定项

依据用户在上一条布局建议后回复“按这个来调整当前实现”。无待用户决定的产品分歧；旧布局兼容属于保留现有行为，不将既有工程自动迁移。
