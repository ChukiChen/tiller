# 仓库分组布局实施计划

用户已确认此前展示的 `repositories/` 分组、标识与路径分离方案，并明确要求调整当前实现。需求和设计已通过现有命令登记；来源见 user-source.md。内部字段与兼容细节是实施方案，不冒充用户逐字审阅。

1. 保存旧 0.3.0 分发基线，建立独立分支并按文件摘要交接当前源码和资料；原目录保持不动。
2. 先补新布局、旧兼容和危险映射回归；统一仓库路径校验及解析，初始化和升级登记明确映射，资源版本更新为 0.3.1。
3. 接入交付准备、活动绑定、业务文档引用、确认边界和工作链接；仓库身份与资料所属范围保持不变。
4. 更新规则、使用示例与长期设计，标明旧布局支持及不自动迁移。需求只补稳定身份及位置关系要求，具体目录归设计。
5. 执行静态检查、类型检查、相关测试、完整回归及本地打包安装；使用分组多仓库做安装后验证。
6. 比较主目录与交接时摘要，无冲突时交回验证成果。检查未初始化测试工程的源/目标绝对路径、Git 状态和身份，再移动业务目录，保持原远端与提交，不初始化、不提交、不推送。

分工：元信息与升级、交付定位、资料引用分别独立实现；主执行者负责资源、文档、版本、整体验证与本地测试工程调整。无新增依赖。旧隔离交付 worktree 保留，本次使用新的 `codex/repository-layout` 分支，不覆盖之前的未提交成果。
