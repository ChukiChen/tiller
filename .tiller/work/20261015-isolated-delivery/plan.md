# 隔离交付开发计划

依据：已确认的工作推进设计第 11 节及 design-isolated-delivery 请求；实际授权见 design-confirmation-source.md。

## 实施顺序

1. 保存设计确认；建立本地隔离分支，清单化交接当前未提交的必要文件，保留源目录。
2. 实现版本化交付记录、Git 身份及活动路径解析、两种管理模式的 prepare 计划与应用、基线交接及只读状态。
3. 实现显式授权的 commit、push、review、merge、reconcile、cleanup；外部能力不足时返回具体限制，未知结果先核对，不虚构成功。
4. 增加 merge 版本绑定及确认格式显式迁移，保留旧确认历史；接入现有工作命令和路径解析。
5. 同步通用入口、规则、CLI 帮助、使用示例及资源版本，保留 0.2.2 升级基线。已有工程通过升级计划应用。
6. 临时仓库验证两种模式、文件交接、过期计划、授权、版本失效、恢复、清理及包安装，执行完整质量检查；核对实际覆盖与剩余平台限制后展示待验收结果。

## 分工与边界

- 环境部分负责 Git 执行、prepare、路径绑定与交付记录基础。
- 操作部分负责提交、推送、评审适配、合入、恢复与清理。
- 确认部分负责 merge 绑定、兼容迁移及相关测试。
- 主执行者负责接口协调、CLI 和规则接入、版本升级、整体验证与文档。

不新增第三方依赖。修改者仅写其负责文件，不覆盖其他人的改动。受控测试采用临时本地仓库及模拟服务；真实托管平台认证和 macOS/Linux 行为未实际验证时如实记录。实现所有已确认命令的可用路径及拒绝条件，不能用仅列出命令代替能力。
