# 工作产物管理开发计划

## 目标与授权

依据本工作记录中的实际用户确认，实现工作推进设计第 3.3、9.2、9.3 节与开发规范设计第 4.2 节。复用既有锁、事务、文件引用和确认检查，不增加运行依赖。交付版本采用 0.2.2；本计划不授权提交、推送、发布或代替用户验收。

## 实施顺序

1. 实现 schemaVersion 2、多产物生成与引用、当前需求依据绑定及按产物完成；旧记录保持只读，写入需显式迁移。
2. 实现无机器登记也可运行的结构检查，以及按明确映射预览、校验、接入历史资料；保留源文件、原始记录、确认及快照。
3. 接入命令参数、错误提示和帮助，更新通用入口及单一工作记录约定；保存 0.2.1 资源基线并支持显式升级。
4. 验证同工作逐步推进、未确认阻断、对象与范围不匹配、历史保护、幂等、变化冲突和恢复；运行全量检查及独立安装验证。
5. 显式升级 tiller 自身及独立 Java 测试工程，比较升级前后文件，检查资料及业务源码保护；同步实现文档，展示交付与未覆盖范围供验收。

## 并行责任

核心产物逻辑、历史接入、资源与升级分别在独立文件范围推进；入口集成、既有用例适配、交付文档和最终验证由主执行者负责。共享类型与接口先协调，避免不同写入者互相覆盖。

## 验证边界

结构检查不等于语义质量、真实用户来源认证或整体软件验收。测试中的批准数据仅为合成样例，不用于真实工程的确认记录。跨平台设计沿用已有约定，实际运行平台与未验证平台分别报告。
