# 任务推进与交付门禁变更需求

> 状态：需求已确认；按用户补充要求，不提供旧记录兼容或迁移。

## 1. 目标与依据

让开发者与 AI 在推进任务和准备交付时，通过程序判断当前范围的前置确认、交付物和验证证据是否满足约定；缺少必要条件时，拒绝对应的受控推进操作，并说明补足路径。

本增量属于工作推进能力，衔接验证与反馈，不增加独立的产品模块。依据为[工作推进需求](../../specs/modules/workflow/requirements.md) FLOW-15、FLOW-20 至 FLOW-24，以及[验证与反馈需求](../../specs/modules/verification/requirements.md) VERIFY-05 至 VERIFY-09。当前实现基线和本次授权见[工作记录](work.md)。

原有文档登记、确认检查和测试报告分别保留；本增量补足从需求到任务、实际产物及证据的推进判断。文档编写完成、任务技术验证通过、整体交付具备验收条件、用户已验收须分别呈现。

## 2. 使用过程与必要产物

| 环节 | 必要信息或产物 | 进入下一步的条件 |
|---|---|---|
| 形成实施规划 | 本次范围、任务清单、需求覆盖、依赖、预期产物及验证条件 | 对具体规划取得有效用户确认 |
| 准备任务实现 | 当前任务的需求、设计、适用规范及确认；前置任务的有效产物与证据 | 必要依据和依赖满足；未满足时仍可整理待审资料 |
| 实现与验证 | 当前任务实际产物、约定测试或人工检查的结果及独立证据 | 必要产物、检查及约定人工节点满足后，记录任务已验证 |
| 准备整体交付 | 本次需求覆盖、全部必要任务、集成回归、交付资料和遗留项 | 统一检查通过后可报告具备验收条件，交由用户验收 |
| 中断或变化后接续 | 已有事实、实际产物、变化范围、失效依据和未结束操作 | 重新核对当前条件，不沿用失效结论或补造过去的顺序 |

交付物按工作目标声明，可包含需求、设计、规范、实现、测试、运行或构建产物、说明及交接资料；不要求所有任务生成整套文档。已有有效资料通过引用使用，跨任务共享产物保持单一来源。

## 3. 功能需求

### GATE-01 登记可检查的规划与任务

应能登记本次范围、稳定任务标识、可观察结果、需求和设计依据、涉及仓库、前置依赖、必要交付物、验证条件及人工检查点。任务允许跨模块、跨仓库和关联多个工作，统一维护其进度与证据。

应发现重复标识、未知依赖、自依赖、循环依赖、无效引用和已声明需求未分配任务的缺口。一个简单任务可采用精简规划；不得把登记成功解释为规划合理或已获确认。

### GATE-02 将规划确认用于任务推进

应能记录并检查具体规划内容、版本、范围及真实用户决定。规划确认不批准尚未展示的任务详细需求和设计，也不代替提交、合入、验收或发布授权。

任务范围、需求覆盖、依赖、完成条件或人工检查点变化时，受影响部分须重新确认。已有仍有效的确认可复用；合并审阅须明确覆盖对象，不因存在另一份批准记录而自动放行。

### GATE-03 检查任务开始条件

受控开始实现前，必须核对当前规划、对应需求与设计确认、适用规范、前置任务的验证状态及相关产物。缺失、被拒绝、失效或必要验证未通过时拒绝开始，列出具体任务、依据及原因；条件满足的独立任务可继续。

空项目的最小可运行骨架使用普通任务规则，依赖它的业务任务不能提前开始。已有项目复用经核对的基础，不机械要求重建骨架。准备草稿、调查和读取记录不被错误视为已经开始实现。

### GATE-04 检查任务交付物与完成条件

应按已确认任务范围检查必要产物是否存在、可定位且与登记对象一致；对适用文档检查实际正文及未填占位，对约定运行或构建产物核对实际生成及验证证据。文件存在不等于内容正确，配置存在不等于程序可运行。

缺少必要产物、证据或人工检查结论时，拒绝将任务标记为已验证。取消、移除或延期必要产物须按范围变更确认，不能通过删掉登记项消除缺口。非必要建议项与阻断项分别呈现。

### GATE-05 用适用验证结果判断放行

任务及整体交付应明确所需用例、类别适用性、回归范围及整体组合验证，复用现有验证结果和证据，不另存一套竞争结论。选择范围应覆盖已声明需求及受影响的跨模块、系统场景，选择依据可审阅；不能仅凭目录或标签排除相关场景。

必要结果为失败、跳过、未执行、无法判断或证据过期时拒绝技术放行。单个套件退出成功不得自动变成全部用例通过；人工检查有实际来源、对象和证据后可作为对应条件的依据。

全局测试目录内与本次范围无关的缺口保持可见，不自动阻断局部工作；本次必要范围不得默认为空。纯文档任务可声明适用的文档检查和人工评审，无需虚构业务测试。

### GATE-06 保留顺序并处理变化和恢复

应记录受控开始、验证及重新核对时的任务、依据、产物版本和结果，能够辨认前置验证与下游开始的实际登记顺序。同轮连续任务仍分别核对，最终测试不能改写为此前已放行。

相关需求、设计、规划、产物、用例或证据变化时，保留原事实，重新判断受影响任务及依赖的有效性。无法确定影响时明确待复核，不静默沿用。正常后续修改引起的复核不得重写先前当时成立的结果，也不要求无变化的独立任务一律重跑。

中断或并发操作后重新检查条件，不能以过期检查结果覆盖较新状态。重复请求不得产生重复的完成事实；未知执行结果保持未知。没有当时受控记录的行为不能补造历史开始或放行；新流程从新建记录及当前核对开始。

### GATE-07 汇总整体交付门禁

应按本次交付范围汇总需求覆盖、必要任务、交付物、有效确认、适用验证、人工检查点和未解决事项，分别给出技术就绪情况、过程证据缺口与验收状态，并定位每项阻断原因。

在受控登记整体技术就绪或满足约定交付门禁的合入操作前，必须重新核对当前结果，不能仅检查一份旧报告文件。缺口存在时允许展示报告、记录用户意见、拒绝或例外，但不能宣称全部技术条件通过。

用户验收、合入和发布仍按各自对象与授权确认。单份需求或设计文档完成只判断其自身条件，不要求整项业务实现已完成。开发中的增量提交、备份推送及草稿评审不因整体尚未完成被一律禁止，仍须满足已有对应授权和操作约束；进入可合入状态时满足适用门禁。

### GATE-08 明确例外、新记录与检查边界

用户明确授权的例外须关联具体对象、条件、范围、理由及当前内容，经有效性检查后仅放行所涵盖操作。报告保留未通过事实与例外依据，不将豁免伪装为通过，不提供无来源的通用跳过方式。

新任务与交付流程只支持本次定义的记录格式，不提供旧记录兼容读取、转换或迁移能力。遇到不支持的记录时明确拒绝用于推进，提示按新格式创建工作。已有文件不自动删除；旧状态、批准和验证结果不自动继承，已存在的规格正文可作为新工作资料引用并重新核对。

两种工程模式遵循同一判断规则：单仓库资料与代码在同一交付范围内核对；独立管理的共同记录集中维护，各仓库按登记身份定位、分别授权并核对版本，不能以一个仓库通过代表整体通过。

程序检查仅约束 Tiller 管理的操作，须明确未检查对象和来源可信度。不能宣称阻止宿主直接写文件或运行 Git、自动认证用户身份、证明内容语义正确，或保证多个仓库原子合入。

## 4. 验收条件

| 编号 | 场景与预期 | 对应需求 |
|---|---|---|
| G-AC-01 | 重复任务、未知依赖、循环依赖及已声明需求漏分配能被指出，登记不产生批准 | GATE-01 |
| G-AC-02 | 未确认或已失效的规划阻止受控任务开始，变更受影响范围后须重核；其他有效批准可复用 | GATE-02、GATE-03 |
| G-AC-03 | 骨架只有静态检查而缺少约定运行证据时，下游实现被拒绝；独立任务可开始 | GATE-03、GATE-05 |
| G-AC-04 | 必要交付物缺失、文档只有占位或运行证据缺失时，任务完成被拒绝并指明对象 | GATE-04 |
| G-AC-05 | 套件退出成功但必要用例未通过，或人工证据缺失、过期时，不放行任务 | GATE-05 |
| G-AC-06 | 局部工作检查其已确认范围及相关跨模块场景；无关全局缺口不混为本次失败，必要范围不能被静默删减 | GATE-01、GATE-05 |
| G-AC-07 | 依次开始骨架、验证骨架、开始依赖任务留下可查顺序；事后整体测试不补造该顺序 | GATE-06、GATE-08 |
| G-AC-08 | 上游产物或必要证据变化后，下游继续操作须重核；历史事实与当前失效分别显示 | GATE-06 |
| G-AC-09 | 中断恢复、重复请求或并发修改不会用过期依据产生有效完成，未知结果不盲目重放 | GATE-06 |
| G-AC-10 | 各任务通过但缺必要组合验证时，整体技术就绪仍被拒绝；检查通过也不自动用户验收 | GATE-07 |
| G-AC-11 | 文档独立交付与授权的增量提交可按自身条件完成，不被错误要求全部业务任务结束；合入核对当前适用门禁 | GATE-07 |
| G-AC-12 | 有效例外只影响明确对象，失败事实保留；无来源豁免被拒绝；不支持的旧记录明确拒绝推进，不迁移、不删除或自动继承状态 | GATE-08 |
| G-AC-13 | 单仓库和多仓库均可核对本次产物与证据；一个业务仓库的成功不能掩盖另一个必要仓库的缺口 | GATE-08 |
| G-AC-14 | 一次真实 AI 推进验证含前置失败、被拒绝、补足、重试及接续，明确受控拒绝和宿主直接操作的区别 | GATE-03、GATE-06、GATE-08 |

## 5. 边界与后续细化

本增量不承担自动拆解产品、自动调度 Agent、替代各语言测试框架或拦截所有宿主操作。任务合理性、文档语义、测试充分性及来源真实性仍由实际评审负责。

具体命令、记录格式、状态转换、确认关联、输入变化的影响判断及与既有交付命令的接入方案由对应设计细化。本需求不固定技术实现，也不声明上述能力已经实现。
