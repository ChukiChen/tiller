本次使用现有 TypeScript + Node.js 工程，不重新搭建骨架。代码基线包含已验证但尚未提交的 0.3.6 测试管理增量，保留其成果；新流程不兼容旧记录，不提供转换或迁移，不删除原文件。

交付候选版本采用 0.4.0，明确工作记录行为不兼容。这只是本地开发与打包目标，不是发布授权。修改仅限 tiller 自身，测试使用受控临时工程；不更新外部测试仓库、不提交、不推送、不合入、不发布。

| T5 整体交付门禁与明确例外 | 必要任务和组合验证未满足时不能登记整体就绪；合入引用当前检查；增量 Git 操作保持授权边界 | T4 已验证 | 新整体评估、delivery-actions、确认、CLI、交付测试 | 单份文档与整体交付分开；就绪不自动验收；例外不篡改失败事实；旧报告、内容漂移与合入限制负例通过 |
| T6 完整交付及真实自举 | 规则、帮助、模板、规格与安装包一致；新工程可按完整流程验证，形成最终证据 | T5 已验证 | resources、README、长期规格、包版本/基线、打包检查、集成与真实流程证据 | 全量回归及打包检查通过；两种工程模式验证；真实 AI 顺序、失败恢复证据齐备；未验证平台和质量指标明确保留 |

每项任务开始前复核当前工作差异、确认有效性及前置证据。需要调整实质范围、完成条件或依赖时更新本规划并确认受影响部分，不能直接越过门槛。任务内必要实现细节自主处理，不额外要求每项技术完成都人工批准。

### T1 边界及完整性

统一落实已确认的新记录版本：work 3、confirmation 3、verification run 2、delivery 2；planning/tasks 为 1。格式升级不是为旧数据填默认值。涉及旧解析、adopt/migrate 分支时按本设计移除对应兼容路径，并更新帮助和测试夹具；不扩大为删除工程历史资料或取消独立的资源升级能力。

T1 必须保持新格式下已有能力可运行，不能只改版本常量造成全部现有命令不可用。若发现新字段只有在后续能力中才能建立，应使用明确未就绪状态，不伪造已通过任务或批准。新确认类型的最低结构及前置校验在本任务完成，规划和任务专用内容检查在 T2/T4 接入。

### T2 至 T5 的执行约定

规划定义与状态分开；共同规划中的任务可以关联其他工作，唯一写入来源保持不变。T3 提供同一证据评估函数供 T4/T5 使用，不复制报告判定。T4 对目录成员变化、生成产物证据、必要文档及人工检查一并核对，不把“存在”当成“通过”。

T5 对普通提交、备份推送、进行中评审仅保持已有授权约束；可合入和整体就绪才接入适用完整门禁。平台不支持源/目标双重原子保护时，继续拒绝自动合入。未解决的外部结果保持未知，不通过重试或补写记录制造成功。

## 4. 验证与当场记录

每项任务使用 Node.js 内置测试覆盖当前增量及受影响既有行为，实际构建后测试 dist，不在测试过程中并发重建同一输出。至少运行类型/构建检查、必要静态检查及本任务行为回归；按变化范围选择检查，不为纯文案重复整套长耗时测试。

每个任务完成时，在本工作 verification.md 保存当时的代码/产物摘要、执行入口、环境、结果、失败与修复及未覆盖项，并关联可共享日志或证据。测试输出不包含凭据和不必要的本机身份。未经提交授权，以内容摘要与事件记录作为版本依据，不强制每任务 Git 提交。

重点负例包括：缺规划批准、前置失败、缺产物、旧格式、代码变化后首次 verify、必要用例未执行、无关全局缺口、伪造套件通过、证据自证、重复操作、并发漂移、事务失败和过期合入判断。连续 verify/status 与 ready/check 必须证明自身记账不会导致循环失效。

T6 在所有必要任务通过后运行完整代码回归和打包验证，验证安装后的固定入口、新格式工作链及拒绝旧记录。真实流程至少包含“前置失败 → 下游被拒绝 → 修复验证 → 下游开始 → 中断接续 → 整体检查”，保留实际顺序，脚本测试或静态规则匹配不能替代真实 AI 行为证据。

性能记录明确数据规模、上限与实测耗时，没有已确认阈值时不宣称性能达标。其他操作系统无法实际验证时保留限制，不冒称跨平台全通过；必要项目条件不能用未执行替代通过。全量技术验证、过程证据、用户验收分别报告。

## 5. 自身开发期间如何记录

目前新任务门禁尚不存在，本计划及逐任务进度先由可读工作记录真实维护，不手写未来 tasks.json 或 planning 确认类型。保留已验证的 0.3.6 管理入口/安装包用于本工作的现有登记；新代码通过独立构建和临时工程验证，避免新解析器拒绝本工作后又被迫“迁移”旧记录。

进入替换记录解析的任务前，核对并固定可用旧版管理入口；本机固定入口只是本次开发记录手段，不会分发为产品的旧记录兼容功能。新能力具备后创建新的自举工作，不把当前工作转换成新状态或补造历史批准。新自举如需人工确认，展示其具体对象，并复用确实覆盖它的实际授权；范围不足时等待相应决定。

资源同步使用正式预览/应用流程保护现有内容。当前工作资料及先前 0.3.6 验证证据保留，不为匹配版本删除或重写。最终保存唯一成果与共享证据；不自动清理工作树。
