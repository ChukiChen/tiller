# 按工作类型选择流程：交付说明

程序、资源与运行时采用同一当前契约 0.5.0。本说明介绍使用方法和交付边界；当前实施状态、实际验证结果、已知限制及 PR 链接统一见本工作 [work.md](work.md) 及验证摘要。说明文件本身不构成测试通过、用户验收、合入或发布结论。

## 使用入口

在按当前契约初始化的工程中，先读取 `.tiller/usage.md`，使用 `node .tiller/run.cjs`。查看 `workflow list/show/check` 后显式选择流程，通过 `work create --workflow … --input …` 登记目标、影响事实、范围、动作来源、预期产物及完成条件。创建不自动开始阶段或执行外部操作。

内置流程包含需求探索、问题分析、技术调研、功能开发、缺陷修复、重构与性能优化、审查、验证、文档维护、升级迁移、发布运维。类型说明本次交付目标；实际动作仍受来源、影响、阶段和确认边界约束。未知影响保留未知，不通过填写 false 降低检查要求。

完整分析流程的 JSON 和命令链只在分发的 `resources/usage.md` 维护；README、入口与规则引用同一来源。本说明不复制第二套输入。

## 接续与交付

用 `work resume`、`work workflow inspect`、`work stage status` 核对当前对象；需要继续失效阶段时，按实际依据先预览再应用 `stage resume`，使用返回的新尝试标识。操作标识不得用于不同内容，工作、阶段、任务修订和整体控制快照分别取实际结果。

报告型流程按其阶段及输出完成，不制造开发需求、设计、任务或 PR。开发阶段明确委托已确认并激活的规划任务，逐任务 start、执行、验证；task verify 不自动完成外层阶段。跨工作依赖与流程转换显式预览，绑定实际对象及证据，保留转换前历史，不继承已失效的权限。

执行套件使用实际 execution/case 选择；人工观察先 capture，再检查当前对象，最后 record 实际结果。任务观察绑定 taskId；任务、阶段和整体的检查与证据不可相互冒充。套件退出成功仍需核对原生失败、取消、跳过及覆盖范围。

整体先 delivery-check，再根据实际 controlSnapshot 预览和应用 delivery-ready。技术就绪、允许保存交付回执、过程证据及用户接受分别报告。验收、合入、发布仍需要各自的真实决定和对象绑定。

## 当前契约

本次不支持旧版本兼容。旧版或未知工程资源、运行时、工作及确认格式明确拒绝，保留原件；不提供自动转换、补写历史或成功续接分支。已有旧资料可在一个新的当前格式工作中明确引用，并核对当前范围与所需依据。

工作及确认记录为版本 4，阶段、规划及任务为版本 1，验证运行、Git 交付及整体回执为版本 2。程序版本与各记录协议分别判断，不凭较高版本号推定兼容。当前显式登记的直接子目录和 `repositories/<id>` 布局都受支持，不自动移动仓库。

本次真实开发曾使用隔离的固定管理程序；候选程序不覆盖该管理安装。本工作旧机器记录已按用户要求清理，保留来源摘要，不创建伪造的新格式记录。

## 验证结果的填写边界

最终报告须引用同一冻结候选的质量检查、原生行为回归、安装包检查及真实宿主演练。分组复用只限输入和构建仍一致、完整执行且有原始输出的结果；定向用例不能冒充整个文件覆盖。汇总分别列出实际执行次数与唯一文件覆盖，不制造一次不存在的“全套运行”。

本工作原始过程文件已按用户要求删除，实际结果及失败、中断边界见验证摘要。Windows 上的实际结果不能表述为其他操作系统已验证；安装演练中的合成批准也不能替代真实用户批准或宿主演练。

读取交付结论时，核对 work.md 和 verification.md 中的当前对象、实际耗时和验证缺口。原始报告已删除，摘要不能替代最后候选尚未完成的完整回归或安装包检查。
