# 功能分块与项目骨架推进设计

## 依据与范围

依据[本次需求](requirements.md)及[真实用户指令](decisions.md#用户指令)，把已讨论的功能分块、骨架优先、依赖推进及确认边界落实到规格、规则和分发。以下记录执行者在授权范围内采用的技术细节，不冒称用户逐字批准后来生成的文档。

## 规则与资料

共同规则新增“功能分块与实施安排”，作为单一执行来源；入口、规则索引、设计、实现和交付规则引用。三个设计模板只补后续实施提示，需求模板保持纯需求。

长期规格新增 FLOW-20、FLOW-21 和 RULE-12，分别定义功能分块、项目基础及执行质量；工作推进设计第 2.3 节说明计划内容、粒度、依赖、按需细化、技术进展和用户验收分离。计划使用现有 work.md 或 plan.md，功能块与工作不强制一一对应，不增加机器记录字段、自动调度或业务脚手架生成命令。

## 版本与兼容

资源和 CLI 升至 0.3.3，保留真实 0.3.2 受管基线供显式升级。0.3.2 与 0.3.3 均有 13 个受管文件，旧 11 文件版本仍按原集合解析；已知旧资源只读检查及显式升级，不把更新 CLI 当成工程资源已更新。原工作、项目资料及自定义修改保持原策略，冲突不覆盖。

本仓库通过正式升级接入新规则。既有测试工程不静默升级，以免改变用户正在验证的条件；新安装包可供随后显式更新。

升级时启动器按当前工程资源版本筛选候选 CLI，下限至少为 0.3.2；本机旧安装不兼容时继续检查有效新绑定及同仓库主副本。工作副本复用安装也采用当前活动工程的版本条件，不能仅因旧 CLI 可以执行 --version 就报告可用；没有兼容安装时明确失败，不自动修改安装或元信息。版本下限不保证未来任意高版本必然兼容。

## 验证

核对新规则读取链路与文档引用；验证新初始化及真实 0.3.2 到 0.3.3 升级、两种管理模式、工作内容保护、冲突保留与版本兼容；执行受影响的核心、CLI、升级、规则、运行入口及安装包检查。文档和技术检查不证明 AI 已按流程完成真实业务，空项目及已有项目实际行为仍需用户场景验收。
