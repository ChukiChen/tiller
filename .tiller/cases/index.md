# 全局用例

本目录保存产品级回归事实，是跨任务回归清单的单一事实来源。`task.md` 只记录单次任务；需要长期保留的验收路径应在这里声明，不复制单次执行日志、全文快照或证据包。

## 文件

- `flow.json`：默认工作流 `start`、`confirm`、`verify`、`check`、`accept`、范围和验收条件映射的精简回归集。

## 字段

| 字段 | 含义 |
|---|---|
| `id` | 跨文件稳定且唯一的用例编号，例如 `CASE-001` |
| `title` | 可读的行为结论 |
| `requirements` | 需求、规则或决定文件引用，可用 `#` 指向章节 |
| `modules` | 用例覆盖的需求模块或关键实现文件 |
| `test_ref` | 自动化测试引用，格式为 `文件` 或 `文件::测试名` |
| `source` | 用例对应的源码路径 |

每个 JSON 文件使用 `{"schemaVersion": 1, "cases": [...]}`。`check` 会校验引用路径、测试文件内的用例名和跨文件重复编号；本次 `verify` 的测试若未命中任何用例 `test_ref`，会给出提示但不替代人工验收。

用例只保存可提交的事实声明。执行结果属于当前任务，按 `task.md` 的“命令、结果、提交、代码树摘要”记录；详细证据从 Git 取回或重跑。
